| A5 | Position is integrated with forward Euler: `x[k+1] = x[k] + v[k] / 16`. Ground-truth velocity is `(x[k+1] - x[k]) * 16`. Ground-truth acceleration is `(speed[k+1] - speed[k]) * 16`, taken from the speed profile, so it is exact (changed from the earlier wording, which used the velocity). The last frame repeats the previous value; with one frame, velocity is the speed and acceleration is 0. Built in `motion.py` (TASK-3). | The decoder will compute the same differences, so the only error left is rounding. | Ground truth would differ from what a decoder sees by a small integration error. |
| A6 | A segment's end speed is reached on the first frame of the next segment. The last segment never reaches its own end speed exactly. Built with `np.linspace(start, end, n, endpoint=False)` (TASK-3). | Follows from a linear ramp over `n` frames. | A one-frame shift at segment ends. |
| A7 | Acceleration is the signed derivative of signed velocity. While driving backward, a negative acceleration means speeding up. | The simplest definition. | Users who expect "negative = braking" must use speed magnitude. |
| A8 | Points are rounded to whole centimetres with round-half-to-even (numpy `rint`) and stored as int32. `place_body` checks the int32 range before the cast and rejects non-finite positions. | A9 | Timestamps start at 0: `timestamp_ns = frame_id * 62,500,000`. | 16 fps gives exactly 62.5 ms. | None. |
| A10 | `seed` is part of the scenario and the hash, but it has no effect until noise exists. | You asked to hash the whole scenario. | A dead field in the meantime. |

| A13 | The measured tolerances (position 0.6 cm, velocity 17 cm/s, boundary 6 frames, duration 8 frames, end speed 40 cm/s) come from one demo drive and a throwaway script that is not in the repo. | Planning needed numbers before code exists. | The property tests may force wider limits; they will be recorded, not hidden. |
